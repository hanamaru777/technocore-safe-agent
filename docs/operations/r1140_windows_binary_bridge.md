# R1140 — Windows PS5.1 native bounded ciphertext bridge

2026-11-02. Requires no Python on owner's Windows machine. This is an internal C# transport component with no live SSH endpoint, private key, signer grant, owner CLI or service activation. It is not deployed.

Why necessary: existing real R1136/R1138 Windows SSH carrier r1079_profile_ssh_transport.cs caps stdout at 16384 bytes and stdin 32768 bytes. A real R1128 AES-GCM preseed can approach 16MiB and R1129 receiver allows up to 32MiB ciphertext. Increasing R1079's limits would weaken already-passed read-only witness behavior. R1140 is a distinct fixed-purpose binary pipe, not a change to R1079 or to original Oracle.

R1140 Bridge.Pump accepts two PREAUTHENTICATED owner-pinned executable/argument pairs and bounded mutable source control. It starts a fixed recipient first, then source, requires initial FLOPST01, forwards at most 32MiB in 64KiB RAM chunks, captures at most 4096 bytes of untrusted recipient status, drains bounded stderr without printing it, stops/kills both children after at most 180s or errors, requires both exit statuses 0. It overwrites caller-provided control buffer even when rejected before launch; it creates no files or directories and cannot decrypt or sign. Windows CI uses only synthetic local Python test processes as fixtures; production bridge itself requires no Python or external package beyond PS5.1 .NET Framework.

Critical trust boundary: Bridge.Pump does NOT authenticate SSH host keys, original R987 V2 escrow, owner Ed25519 signed R1128 DATA export approval, original instance machine ID, actual K137 endpoint/pinned public host key, destination ACL/disk reserve, or final R1129 report schema. Its RecipientReport is raw untrusted bytes and MUST be strictly parsed and compared to actual forwarded count by a separately reviewed owner launcher before it is ever printed/accepted. No owner launcher is included, so nothing should be executed against real Oracle or K137 from this task.
