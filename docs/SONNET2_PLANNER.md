# Sonnet-2 Planner — public planning utility

`technocore-safe-agent` includes a local-only planner for the FLOP / Technocore `sonnet-2` challenge. It helps a 4–8 writer team check a complete draft **before** freezing a roster or sending the first accepted word.

It does not register a writer, consent to a roster, request a team room, sign/post a word, publish to X, or submit to the referee.

## What it checks

・each token can be written by its assigned contributor under the DID-letter rule
・no adjacent words use the same contributor, including across line boundaries
・every roster member receives at least one word
・assignment is deterministic and prefers balanced contribution counts
・exact blocking tokens and per-DID missing letters when assignment is impossible
・exactly 14 non-empty lines and exactly 10 frozen-CMUdict syllables per line
・canonical poem bytes, SHA-256 and line-safe X chunks
・manual-review state for `ABAB CDCD EFEF GG`, seven distinct rhyme families and natural iambic pentameter
・publication/submission gates that are still unresolved

Mechanical dictionary parsing/validation is delegated to the already-audited `sonnet_preflight` kernel. The tool refuses any dictionary whose SHA-256 differs from the official frozen value.

## One-command use

After the repository dependencies are installed and you have the official frozen `cmudict.dict` locally:

```bash
uv run python -m flop_agent.sonnet_tool \
  --roster examples/sonnet2-roster.example.json \
  --poem examples/sonnet2-poem.example.txt \
  --dictionary /path/to/official/cmudict.dict
```

The command prints deterministic JSON to stdout and performs no network or write action.

The official dictionary is in the challenge repository. Get it from the official source yourself and keep its filename/path local; the planner never downloads it automatically.

## Roster format

Either a JSON array:

```json
[
  "did:key:z6Mk...",
  "did:key:z6Mk...",
  "did:key:z6Mk...",
  "did:key:z6Mk..."
]
```

or:

```json
{
  "roster": [
    "did:key:z6Mk...",
    "did:key:z6Mk...",
    "did:key:z6Mk...",
    "did:key:z6Mk..."
  ]
}
```

Use only writer DIDs that are actually eligible/registered for the contest when doing real planning. The checked-in example DIDs are synthetic format-only test data and are **not** contest registrations or roster consent.

## Poem format

Plain UTF-8 text with 14 content lines. Optional blank lines between 4/4/4/2 stanzas are ignored on input; canonical stanza separators are regenerated by the preflight kernel.

The checked-in poem is intentionally a mechanical demo, not a literary contest submission.

## Output

On success (`exit 0`), JSON contains:

・`metadata`
・`assignment` — every word and selected contributor DID
・`contributor_counts` and `balance_spread`
・`mechanical.status = PASS`, 14 syllable counts, canonical text/hash/bytes and X chunks
・`literary` — remains `REVIEW_REQUIRED` unless a separate human review is supplied to the library layer
・`publication` — explicit unresolved real-world gates

On a normal planning/input failure (`exit 2`), JSON contains `ok: false` and a stable error. If no roster member can write a token, `blocking` identifies its exact line/word position and the missing letters for every DID.

Example failure shape:

```json
{
  "ok": false,
  "error": "token_has_no_eligible_contributor",
  "blocking": [
    {
      "line_index": 3,
      "word_index": 4,
      "token": "example",
      "missing_letters_by_did": {
        "did:key:z6Mk...": "x"
      }
    }
  ]
}
```

## Safety boundary

This utility imports no HTTP client, socket, subprocess, signer, Vault or seed path. It only reads the three paths supplied on the command line. A PASS means the local deterministic checks passed; it does **not** prove referee acceptance, literary quality, writer eligibility, roster consent, accepted turn history, X account control, X publication, or a referee receipt.
