# Oracle Resident package

This is a reviewed deployment package, not an installer that runs itself. It targets Ubuntu and Oracle Linux, uses the unprivileged `technocore` user, keeps root-managed Discord configuration in `/etc/technocore-safe-agent/env`, and puts public observer/resident state in `/var/lib/technocore-safe-agent`. It never requests, copies, or stores a DID seed.

After review, root may run `./install.sh REPOSITORY_URL` (or add `--discord` for the optional Discord dependency and unit). It clones the repository, installs locked dependencies, writes units, and calls `daemon-reload`; it never enables or starts either service. Review the empty `env` file and explicitly enable services afterwards.

`update.sh` fast-forwards `main`, syncs dependencies, runs secret scan and doctor, and restarts only services that are already active. A failed preflight leaves the running process untouched. `healthcheck.sh` checks the resident process plus observer health and state freshness. `import-state.py` accepts only the current relative-layout export, validates every manifest hash and JSON object, rejects zip-slip/duplicates/flat legacy exports, makes a backup before overwrite, and writes state atomically.

For the optional Windows session transport, `install.sh` installs the root-owned `/usr/local/libexec/technocore-safe-agent-rpc`. It accepts exactly `export` or `ack`, clears the caller environment, drops to `technocore`, and uses only `/var/lib/technocore-safe-agent`, `/opt/technocore-safe-agent/src`, and the project virtualenv. It has no signer or Technocore write path. Provision a restricted SSH login account separately, then review and adapt `technocore-safe-agent-rpc.sudoers.example` with `visudo`; the installer deliberately does not create that login account or install this authorization.

## Existing-VM isolated signer

For the existing `technocore-resident` VM only, root may run `/opt/technocore-safe-agent/packaging/oracle/prepare-signer.sh` after updating the checked-out repository. For a fresh installation, use `./install.sh REPOSITORY_URL --signer`. Both create the non-login `technocore-signer` user, a private receipt directory, a shared non-secret outbox group, and install but do not enable `technocore-safe-agent-signer.service`. They install the OCI SDK as an `oracle-signer` extra. No new VM, OCI Function, seed file, or automatic enablement is involved.

Before enabling it manually, create `/etc/technocore-safe-agent/signer.env` from `signer.env.example` as root:root mode 0600. It contains only the OCI Vault Secret OCID, the already verified public DID, and a poll interval. Store the actual 64-hex seed only as the CURRENT value of that Vault secret. Give the instance dynamic group only `read secret-bundles` permission for the secret's compartment; do not give the `technocore` user a Vault configuration, signer environment file, or metadata access.

The resident and Discord units deny `169.254.169.254` through systemd. The installed root-owned `technocore-safe-agent-metadata-block.service` reapplies fixed egress denial for `technocore` and `technocore-rpc` on every boot; after review, an operator must explicitly enable that unit before starting resident, Discord, or RPC use. The signer is deliberately excluded and alone receives the root-only signer environment and may use the instance-principal route. Shared outbox/audit files live in `$FLOP_STATE_DIR/autopilot/`, not `observer/`; only that directory, the nonce/activity files, and read-only verified DID are shared with the signer. It accepts no arguments, consumes only strict local intents, renders tracked public templates, keeps a prepared receipt before posting, and re-reads rather than reposting after an interrupted post. It retrieves the Vault seed only around each official signer child process and clears `SIGN_SEED` afterwards.

For a stopped legacy resident with an oversized observer state, first run `python -m flop_agent.cli compact-observer-state` for a dry-run report. Run the same command with `--apply` only after reviewing it; it creates a same-directory backup before atomically writing compacted state. `/usr/local/libexec/technocore-safe-agent-diagnostic` reports state sizes, service memory/restarts, and small heartbeat ages without parsing the large state files.
